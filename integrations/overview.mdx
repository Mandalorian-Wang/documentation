This section is the routing page for framework-specific integration docs. Use it after you already understand the BoxLite product boundary and have chosen the SDK path you want to embed.

## Integration philosophy

BoxLite provides the execution layer. Higher-level agent frameworks decide when to call tools, how to manage conversation state, and how to present results.

The integration model stays the same even when the calling framework changes:

1. Define a tool contract.
2. Receive a tool call from the framework.
3. Execute the requested work inside BoxLite.
4. Return the execution result to the framework.

## Choosing the right page

- Use a framework page when your agent stack is already chosen.
- Use the direct SDK path when BoxLite itself is the first integration decision.
- Keep framework-specific code on the framework pages instead of duplicating it here.

## Best practices

1. Start from a BoxLite quickstart before adding an orchestration framework.
2. Keep BoxLite responsible for execution, not for higher-level agent memory or planning.
3. Reuse a box only when state continuity is part of the product behavior you want.
4. Treat this page as a directory, not as the canonical place for runnable framework code.
