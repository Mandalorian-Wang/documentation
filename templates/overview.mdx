Templates let you turn a prepared Box environment into a reusable starting point. They are useful when setup takes time and you want future Boxes to start from the same known-good state instead of repeating provisioning work every time.

## What a Template Is

A template is a reusable Box starting point created from a configured environment. It builds on top of a base OCI image and captures the customizations you want new Boxes to inherit, such as installed packages, copied files, tool setup, and environment configuration.

When you create a Box from a template, the new Box starts from that prepared state, but it is still its own independent Box.

## Choose Between Image, Template, and Snapshot

Use these three concepts for different jobs:

| Use this | When you need | Best fit |
|---------|---------------|----------|
| **OCI image** | A base runtime such as Python, Node.js, or Ubuntu | Start from a standard image and configure from scratch |
| **Template** | A reusable prepared environment | Pay setup cost once, then reuse it across many Boxes |
| **Snapshot** | A saved point-in-time state from a Box | Freeze progress, restore later, or branch experiments |

### The Short Version

- Use an **image** when you only need a base operating system or language runtime.
- Use a **template** when you want many Boxes to start from the same prepared environment.
- Use a **snapshot** when you want to save the current state of a Box and return to it later.

## Why Templates Matter

Templates are most useful when Box setup is non-trivial:

- Installing the same dependencies every time slows down startup
- Teams need consistent environments for development or automation
- AI agents or jobs need a known toolchain before they begin work
- CI or batch workloads should start from a pre-provisioned baseline

If setup is lightweight and only happens once, starting directly from an OCI image is often simpler.

## Common Template Scenarios

### AI Agent Environments

Prepare a Box once with the packages, tools, and configuration an agent needs, then create many agent Boxes from that same baseline.

Examples:

- Data analysis agents with pandas, numpy, and plotting libraries
- Code review agents with linters, formatters, and security tools
- Automation agents with browser, CLI, or language-specific dependencies

### Reusable Team Toolchains

When every developer or job needs the same environment, templates reduce setup drift and remove repeated manual provisioning steps.

### CI and Batch Workloads

Templates work well when jobs should start fast from a consistent prepared environment rather than rebuilding dependencies each run.

## Template Lifecycle in Practice

The normal workflow is simple:

1. Start from an OCI image.
2. Install dependencies and copy in the files or tools you need.
3. Create a template from that configured Box.
4. Create future Boxes from the template instead of reprovisioning from scratch.

## What Templates Are Not

Templates are not the same thing as:

- **Volumes**: persistent storage attached to a Box
- **Snapshots**: saved state from a specific Box at a specific moment
- **OCI images**: the original base image templates build on top of

Templates solve the “prepared starting point” problem. Snapshots solve the “save current state” problem.
