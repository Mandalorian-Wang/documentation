Use this page as the decision point for BoxLite networking. Start here when you need to answer three practical questions:

1. Should this box have network access at all?
2. If it does, does it only need outbound access or should it expose a service back to the host?
3. Do I need to restrict where it can connect?

This page stays at the product level. It explains the available models and when to use each child page. Detailed implementation, diagnostics, and production tradeoffs live elsewhere.

## Default Behavior

Networking in BoxLite is an explicit choice, not an always-on assumption.

- Use **no network** when the workload should stay fully isolated.
- Use **outbound access** when the box needs to call external APIs, download packages, or reach internal services.
- Add **port forwarding** when a service inside the box must be reachable from the host.
- Add **egress control** when outbound access should be limited to approved destinations.
- Use **private connectivity** only when you need internal-only communication patterns that go beyond ordinary outbound access.

## Choose the Right Model

| Need | Recommended model | Read next |
|---|---|---|
| Run code with no external communication | No network | [Troubleshooting](/networking/troubleshooting) if commands unexpectedly fail |
| Download dependencies or call external APIs | Outbound network access | [Egress Control](/networking/egress-control) if you need restrictions |
| Reach a web server or API running inside the box from the host | Port forwarding | [Port Forwarding](/networking/port-forwarding) |
| Keep traffic limited to approved domains or ranges | Outbound access with restrictions | [Egress Control](/networking/egress-control) |
| Build internal-only service topologies or controlled box-to-box access | Private connectivity | [Private Connectivity](/networking/private-connectivity) |

## Service Exposure Model

The most common mistake in BoxLite networking is to treat ordinary outbound access and service exposure as the same thing. They are different.

- **Outbound access** means the box can initiate connections to something else.
- **Service exposure** means something outside the box can reach a service running inside it.

For most application workflows:

- Start with outbound access only.
- Add port forwarding only for the specific ports you need.
- Avoid broader network exposure until there is a concrete reason.

This keeps the sandbox model easier to reason about and avoids accidental reachability.

## Implementation Notes

BoxLite uses user-space networking components to provide outbound access, port mapping, and isolation boundaries between the host and each box. Those details matter when you are debugging the runtime itself, but they are usually not the first thing an application developer needs to choose a working networking model.

If you are trying to ship an application, start from the access model above. If you are trying to debug internals, continue to [Architecture: Networking & Storage](/architecture/networking-storage).
