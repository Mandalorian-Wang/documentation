BoxLite is an open source project. This page describes the security posture of the documentation set itself:

- it does **not** define a contractual SLA
- it does **not** promise enterprise support response times
- it does **not** claim bug bounty rewards
- it does **not** claim compliance certifications unless they are published elsewhere by the project maintainers

Use this page to understand how security issues should be treated in the BoxLite docs and what kinds of guarantees are intentionally **not** being made.

## Scope

This page applies to the BoxLite open source project and its documentation.

It does not create:

- a managed service commitment
- an uptime guarantee
- a paid support promise
- a legal compliance attestation

If BoxLite later publishes a dedicated trust center, `SECURITY.md`, or formal disclosure process, that should become the canonical source instead of this page.

## Reporting Security Issues

If you discover a security issue:

1. Gather a minimal reproduction.
2. Describe the affected version, platform, and configuration.
3. Avoid publishing sensitive exploit details until maintainers have had time to assess the issue.
4. Use the project's official public reporting channel if no private disclosure path is published.

At the time this documentation was revised, this docs repo did not define a separate contractual security response workflow.

## What This Page Does Not Promise

This page deliberately does **not** promise:

- first-response timelines
- remediation deadlines
- bounty payouts
- compliance mappings such as SOC 2, HIPAA, PCI-DSS, or GDPR certification status
- enterprise-only security features

Those claims should only appear when they are backed by a real published program from the project maintainers.

## Responsible Documentation Standard

Security documentation in BoxLite should follow these rules:

- do not claim features that have not been verified in the product
- do not imply hosted-service guarantees for an open source project
- do not present conceptual examples as product commitments
- do not mix architecture explanation with legal or commercial assurances
